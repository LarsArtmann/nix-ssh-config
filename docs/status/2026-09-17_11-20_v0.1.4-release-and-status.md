## Headline

v0.1.4 is **out and green**: 12 commits shipped (PAM 2FA fix + prompt-path VM proof + port property tests + CI/docs/process hardening), full local gate green, both CI architecture jobs green, GitHub Release object exists with CHANGELOG-derived notes.

The release only happened because a **release-blocking bug in `scripts/release.sh` was found and fixed mid-flight**: the compare-link HTTP guard could never pass for a brand-new tag (GitHub 404s compares of unpushed tags), so the script — whose only CI proof tested the already-existing-tag path — had never actually been able to release a new version. The bug is fixed; the vacuous-proof class it exposed is the most important finding of this session.

## g) Questions I cannot figure out myself

1. **Should this have been 0.2.0?** I judged patch (0.1.4) because the only consumer-visible change is the PAM fix and no public options/outputs changed — but the PAM fix _changes default module behavior_ (`security.pam.services.sshd.unixAuth = true` gets forced on the prompt path), and the VM-test/prompt-path additions are substantial. If you consider behavior changes minor-bump-worthy in 0.x, this was the wrong call and the CHANGELOG section header (and future tags) should follow the corrected convention. Your answer defines the rule for #16.
2. **What is the acceptable reliability posture for CI's cache layer?** The 418 rate-limit class (yesterday) and the `cache.home.lan` 502 class (documented machine-local) are both "substituter fails mid-gate". Options: (a) drop magic-nix-cache entirely — slower, deterministic; (b) keep it and auto-rerun failed jobs — fast, masks real failures; (c) self-host/switch cache — durable but new infra. I cannot decide how much CI flakiness you are willing to trade for speed.
3. **Are archived planning/status docs frozen?** dprint realigned tables inside point-in-time historical reports (`e3da0f1`), rewriting formatting inside records whose value is that they capture a moment. If archives should be immutable (my lean), treefmt needs an exclusion — but that partially reverses plan 3's "format everything" decision (D1), which was yours to make and is yours to unmake.
